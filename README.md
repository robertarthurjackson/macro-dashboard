# Macro Dashboard

**Live dashboard → https://robroth.ca/macro-dashboard/**

A static, self-updating macro & global-liquidity dashboard, published on GitHub
Pages. All data comes from free public sources — FRED, yfinance, SPDR, iShares,
the NY Fed, Treasury FiscalData, OFR, and BIS — refreshed daily by GitHub
Actions. No backend server.

**Sections**: macro watchlist · yield curves & forward curves · repression
signposts (real 10Y, breakevens, 5y5y) · debasement watch (GLD tonnes-in-trust,
IBIT BTC-in-trust, Fed balance-sheet throttle) · velocity board (z-scored
1W/1M moves) · fiscal (Gromen true-interest-expense, rollover ratchet) ·
r-star & policy gap · global liquidity composite (Howell-style) with
BTC/SPX/gold overlays.

## Setup (one-time)

1. Create a GitHub repo and push this project.
2. Repo → Settings → Secrets and variables → Actions → add `FRED_API_KEY`
   (free key from https://fred.stlouisfed.org/docs/api/api_key.html).
3. Repo → Settings → Pages → Source: **GitHub Actions**.
4. Actions tab → run the `build-and-deploy` workflow once manually.

The site then lives at `https://<user>.github.io/<repo>/` and rebuilds daily.

## Local build

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
echo "FRED_API_KEY=..." > .env
python build.py                 # writes site/data/*.json (a few minutes)
cd site && python3 -m http.server 8080   # http://localhost:8080
```

## Architecture

- `build.py` — stateless daily build: fresh SQLite workspace → full backfill →
  export every frontend payload as JSON under `site/data/`.
- `payloads.py` — payload builders mirroring the private dashboard's API.
- `macro_collector.py` / `liquidity.py` / `fred_client.py` etc. — collectors
  (synced from the private vol-dashboard project).
- `site/index.html` — generated by `gen_frontend.py` from the private
  dashboard's frontend (macro + liquidity sections only); a fetch shim maps
  `/api/*` calls to the static JSON.
- `seed/ibit_btc.json` — accumulated IBIT BTC-in-trust history (iShares
  publishes only current-day holdings; the workflow appends one point per day
  and commits it back).

## Known limits

- Data is daily-refresh, not intraday; the header shows the as-of date.
- IBIT flow (4-week Δ) needs ~4 weeks of accumulated seed before it plots
  (accumulating since 2026-08-28).
- October 2025 CPI was never published (government shutdown), so the October
  2026 CPI YoY point is skipped by design rather than mis-computed.
